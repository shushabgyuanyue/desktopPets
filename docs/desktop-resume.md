# 桌面恢复与图标补片刷新

2026-11-06：修复“切回桌面仍要点击一次”和图标替换出现背景块的问题。

## 已发现的缺口

- 前台分类只认 Progman / WorkerW / DefView。“显示桌面”后焦点可能仍在任务栏，或短暂留在已经最小化的窗口上，点击空白桌面才会变成旧逻辑认可的状态。
- 原生探针只推送分类变化；同为 desktop 时，系统再次隐藏/最小化桌宠不会触发主进程恢复。
- 主进程只检查 isVisible，没有专门恢复最小化状态，也没有在新画布准备好之后主动提交透明表面。
- 图标补片异步加载期间使用深色占位块；移动图标时沿用旧位置背景。原测试甚至要求沿用旧补片，导致背景接缝成为预期行为。

## 实现

任务栏、空前台及已最小化/被 DWM 隐藏的前台状态，会枚举主屏上的可见应用。仅在桌面确实露出时报告 desktop，避免只要任务栏获得焦点就把蚂蚁画在其他应用上。排除桌宠自身、桌面宿主、任务栏、工具窗口、屏幕外及最小化/被隐藏窗口。

原生监听增加最小化与切换结束事件，保留每 250ms 的当前状态心跳；稳定桌面不重复刷新画布。主进程在隐藏/最小化时重新发送恢复指令，临时禁止窗口抢焦点后恢复，并主动 invalidate。预加载层提供单向 frame-ready 通知；渲染恢复、页面重新可见及补片解码完成后主动提交画面。窗口禁用普通最小化能力，同时保留系统强制最小化的恢复兜底。

食物与传送门仅在当前坐标对应的补片就绪时替换原生图标，不画深色占位块，不复用其他位置的补片。等待期间保留原生图标；补片就绪立即重绘，无需点击。图标移动、名称及文件回收语义不变。

## 验证与边界

- 62 项单元测试通过；新增断言覆盖最小化恢复、恢复时不抢焦点、稳定心跳不重复刷新。
- 真实 Electron 窗口最小化测试：从 minimized=true 恢复到 false，显示 36 只蚂蚁、完整尺寸画布及待执行帧，不发送点击。
- 原生前台双进程测试：无连续焦点查询也收到 desktop → other → desktop，探针正常退出；原生编译及 PowerShell 兜底编译通过。
- 补片测试：移动时不绘制旧背景；取消动画帧之后释放异步补片，仍能自动画出新背景，不依赖点击或手动 draw；文件名区域透明，拖动读取仍有上限。
- 门户与可见性集成测试通过：隐藏时模拟继续，画布停止提交，恢复主动绘制。
- 电脑操作工具初始化失败（failed to write kernel assets / os error 3），因此没有宣称完成用户实际“显示桌面”按钮路径的实屏验收。上述窗口生命周期与像素检查由独立 Electron/原生测试完成，未操作用户文件。
